02 / App Journey

九个页面，一条可恢复的创作路径

保留现有炭黑、磨砂和粉紫渐变风格。主界面英文，支持简体中文；照片原件与高分辨率输入全程保留。

A · 输入与描述
  1. 创作首页拍照、相册、Files 或纯文字；最近项目和示例。
  2. 拍摄与主体确认裁剪、方向纠正、单主体提示；权限拒绝仍可选图。
  3. 照片 + 提示词说明造型、风格与候选数量，先展示概念费用。
B · 概念与选择
  1. 生成进度阶段状态与已保存草稿；离开页面后仍能恢复。
  2. 多个概念分别放大、对照原图与选择；选中不会自动扣 3D 费用。
  3. 修改并确认保留旧版本；选定输入后单独报价并生成模型。
C · 资产与使用
  1. 3D 结果旋转检查前后与底部，查看纹理、导出、反馈缺陷。
  2. 我的资产库概念、模型与任务统一管理，跨端同步拥有的作品。
  3. 选择游戏匹配角色类别，由用户主动进入；退出返回原资产。

设计板为既有排版参考，实际 UI 使用原生控件；最终图片分辨率、模型纹理和几何质量分别验收，不能互相替代。附加页面包含登录、钱包、购买、设置、支持与账户删除。

03 / Pricing Architecture

手机易懂，桌面灵活

首版只突出一次性包与周订阅。所有点数都可按操作自由使用；展示的完整组合是一种兑换方式，不是与其他方式叠加赠送。

电脑端 · 一次性 Pay by Token

充值包一次性价格Tokens标准完整组合
Craft Token 是产品创作点数，不是模型的语言 Token，也不是可交易代币。Web / CLI / MCP 共用价目表，不额外收 MCP 接入费；跨端打开已有资产不重复收生成费。

每一次收费，都有对应交付

操作Tokens模型中的变动成本假设可售状态

拍照、输入描述、查看已有资产、标准 GLB 导出、重复下载和兼容游戏试玩不收生成点数。系统失败释放或退回额度；用户主动新建修改版本需再次确认报价。未来能力不在首版付费墙销售。

04 / Pricing Workbench

每个价格，经得起多少使用？

修改套餐、渠道费与成本压力，比较全部付费点数未来被兑换的情景。以下是规划假设，不是供应商账单，也不是净利润。

费用按所选渠道匹配，iOS 不套用 Web 卡费。风险准备金不随成本倍率放大；单独从销售额计提。

查看公式与未计入费用

未计税、汇率、国际卡附加费、获客、免费体验补贴、工资与固定基础设施。付费余额不失效，因此不以“用户没用完”作为利润来源。最贵用法用连续上界估计，实际整数操作可能留少量余额。

05 / Transparent Purchase

用户看到的是明确的创作承诺

美国美元的设计文案预览。实际 App 应使用 StoreKit 的本地化商品价格；这里的按钮仅为示意，不会购买、扣费或发放点数。

不隐藏的购买规则

  • 总价、扣款周期和本次到账额度同时出现。
  • 概念图与模型用 “以及 / and” 说明完整组合。
  • 新的修改、高级模式和额外生成按价目表使用点数。
  • 每周自动续订；一次性包明确不订阅。
  • 已购点数不过期，取消不删除已有资产。
  • 首版周套餐没有订阅免费试用，不混淆免费概念体验。
  • 恢复购买只同步权益，不重复赠送已消费的点数。
  • 条款、隐私、恢复、管理订阅与支持在 App 中必须真实可用。

日体验以一次性包满足，首版不做日自动续订。月付与更高周额度只在留存和成本验证后开放；它们在计算器中标为实验／后续方案。

06 / Delivery Roadmap

8–10 周，以验收推进

按一名 iOS 工程师、一名后端工程师及部分设计 / QA 支持估算。阶段有交叠，是工作量预算，不是上线日期承诺。

P0 · 第 1 周

技术与质量基线

原生项目、相机 Spike、3D 格式验证与代表输入评测。

门槛：两档真机显示正确，确认可售类型和成本。
P1 · 第 2–3 周

账户与可靠任务

私有上传、草稿、持久队列、独立生成阶段与钱包。

门槛：用户数据隔离，重启和重复提交不双扣。
P2 · 第 3–5 周

原生创作主流程

概念生成、版本选择、独立 3D 确认、模型查看与导出。

门槛：真实照片到可下载模型，断网及后台恢复通过。
P3 · 第 5–6 周

付费与透明用量

IAP 与 Web 充值、服务端验证、付费墙、钱包流水。

门槛：初购、续费、退款、恢复和重复通知验收。
P4 · 第 6–7 周

资产体验与试玩

跨端资产库、一个兼容角色游戏、方向修正与中英文。

门槛：真正使用指定角色，加载失败有可恢复路径。
P5 · 第 8–10 周

受控付费 Beta

质量回访、实际成本对账、小额付费测试与审核材料。

门槛：成功率、可用质量和单位贡献达标再扩大。
开发前必须修复：概念选择自动触发模型、装饰性余额、未明确的图片分辨率、任务持久化与多用户隔离。产品承诺应由真实状态与账本支持。
