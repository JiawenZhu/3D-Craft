# 3D Craft · iOS 创作体验设计

日期：2026-09-09。交付：三张高保真设计板，共九个页面状态，同一套视觉方向。

这是原生 iOS 产品的视觉提案与交互说明，尚不是可运行 App、Figma 组件库或真实生成结果。图中的角色、游戏封面、账户头像及数字用于设计演示。“3D Craft”暂作移动端展示名；现有网站品牌不因此修改。

## 一、整体方向

延续网站的炭黑画布、磨砂面板、细边框和珊瑚粉到淡紫的强调色。让作品占据最大视觉面积，控件服务于作品，避免把桌面生成参数原样塞进手机。大角色展示体现亲近感，底部主要按钮负责推动流程；大量专业参数收进详情或后续高级选项。

产品主线为：**拍照 / 相册 / 文件 → 提示词和风格 → 多个概念 → 选择和修改 → 明确确认生成 3D → 查看 / 导出 / 试玩**。生成概念与生成模型是两次不同的操作。挑选缩略图不会自动开始 3D 任务，模型完成不会自动进入游戏。

参考图借鉴的是布局与表现手法，最终颜色、面板及操作视觉来自现有网站。

## 二、九个页面的交互规则

### 01 · 创作首页

让用户立即看到照片可以变成怎样的角色。Camera、Photos、Files 并列，直接对应真实拍照、相册图片与文件导入。首次用户的 Recent creations 改成清楚标注的 Examples；自己的作品出现后替换示例。示例不计入个人资产数。

底部固定 Create / Library / Profile。登录不应成为看示例的前置条件；需要跨设备保存或开始账户相关任务时显示登录入口，返回后保留照片和草稿。

### 02 · 照片选择与主体确认

显示完整主体及裁剪范围，支持更换、旋转和重新拍摄。裁剪提示帮助用户减少背景干扰；不能把裁剪框表现成已完成高质量自动分割的证明。

照片中有多个主体时，需要确认要生成哪一个。无法可靠识别时，提示重新裁剪或换图。相机权限被拒后仍可进入相册或文件；上传失败保留本地选择并允许重试。

### 03 · 提示词与风格

在同一页保留参考图、自然语言描述、风格选择及概念数量。第一版建议以少量经过验证的风格开始。数量选项必须匹配后端实际支持能力，图中的 2 / 3 / 4 是设计提案。

键盘出现时，输入区保持可见，主要按钮随可用空间移动；页面可滚动。照片和文字的改动持续保存为草稿。正式收费后，提交前展示后端计算出的额度消耗，不使用前端静态假余额。

### 04 · 概念生成中

以真实阶段显示任务：照片准备、概念生成、等待检查。不知道准确进度时使用不定进度动效，不编造百分比或剩余秒数。用户可以离开并在资产库找回任务。

“项目已保存”和离开后恢复的文案，应在服务端持久化、账户归属及任务恢复实际完成后启用。失败时保留原图和提示词，并提供重试与修改输入。

### 05 · 概念选择

一张主图加三个缩略图保持关注点清晰。缩略图使用编号、边框和勾选共同标记状态，不能只靠颜色。点击切换主图；放大检查脸部、四肢、背包和整体轮廓。

“Try new concepts”保留旧版本。不要覆盖用户已选中的方案。选择完成进入检查页，允许直接确认，也允许继续修改，不强制用户修改一次。

### 06 · 概念修改与确认

自然语言修改作用于选中的概念。修改提交后明确显示进行中状态；未返回结果时，禁止把旧图误认为新版本。保留撤销或版本切换，尤其是用户要求保留的面部、服装和配色。

“Generate 3D asset”绑定当前明确选定的概念版本。确认后进入独立的 3D 任务状态：排队、几何生成、纹理处理、文件准备等阶段应依真实后端能力映射，不假设所有引擎都有同样流程。

### 07 · 3D 资产查看

中心展示完整模型，支持旋转、缩放、重置视角、光照切换；Material / Solid / Wire 对应不同检查方式。检查底部和背面同样重要，默认转台动效可用于帮助发现缺陷，触摸时停止。

模型数据从实际文件提取。GLB、94k 三角形和 10.4 MB 是画面示例，不能硬编码为所有模型信息。“3D ready”只表示模型文件已准备好，不表示自动绑定、动画或所有引擎兼容。

导出展开格式与用途选择。仅显示当前真正支持的格式；iOS 预览所需的格式转换另行验证。主要试玩入口延续现有网站能力，但仍需用户主动点击。

### 08 · 资产库

资产与概念有不同标识，可搜索和筛选。正在生成的任务保持在列表中，失败任务提供解释和恢复入口。新用户空态是“Create your first asset”，而非假作品。

删除要解释是否同时删除云端文件、概念版本和设备缓存。离线时可以显示已缓存的预览，但明确标识不能执行的云端操作。多设备同步要使用同一资产 ID 和版本关系。

### 09 · 选择游戏

使用当前资产缩略图、名称和类型确认“带哪个模型进入游戏”。根据现有兼容规则展示游戏，用户可以修正分类和朝向：

| 资产类型 | 现有推荐游戏 |
| --- | --- |
| 车辆 | Emberfront、Coastline Rush |
| 普通角色 | Lanternfall、The Last Signal |
| 飞行角色 | Emerald Skies、Lanternfall、The Last Signal |

依据当前 `src/lib/gameAssetRules.ts` 和 `src/components/games/GameHub.tsx`。游戏封面为设计氛围示意，不代表当前实机画质。模型加载失败应返回可恢复界面，不静默换成默认角色。现有替换能力不等同于任意角色自动骨骼绑定。

## 三、视觉与原生交互规格

以下是落地时的设计目标，图片为栅格提案，不能直接当作精确组件尺寸。

| 项目 | 建议值 / 规则 |
| --- | --- |
| 设计基准 | 390 × 844 pt，兼容小屏；实际 App 遵循系统安全区 |
| 页面左右边距 | 20–24 pt |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 pt |
| 主背景 | `#121317`，沿用网站 |
| 面板 | `rgba(28,29,33,.72)`，避免过多层叠模糊 |
| 边框 | 白色约 10%，选中态另加明显轮廓与勾选 |
| 强调色 | `#E6765D → #D19EE9`，主要用于主操作和少量标题 |
| 字号 | 大标题约 28–32 pt；正文 16–17 pt；辅助 13–14 pt |
| 字体 | iOS 系统字体；支持动态字号，中文采用系统中文字体 |
| 交互目标 | 至少 44 × 44 pt；主按钮高约 52–56 pt |
| 圆角 | 按钮 16–20 pt，内容卡片 20–24 pt；避免所有区域都套卡 |
| 图标 | 落地时统一 SF Symbols 或同一套授权图标，不混用生成图中的图标 |
| 动效 | 轻量淡入、缩放和选择反馈；遵循减少动态效果设置 |
| 触觉 | 选择、任务提交及完成采用克制的反馈，不连续震动 |

每页保留一个明显的主要下一步。错误、状态及选中不能只依赖红绿颜色。VoiceOver 应能读出概念编号、是否选中、生成状态及按钮用途；3D 视图另外提供明确的重置和旋转操作。

## 四、英文与中文

设计图以英文为主；应用保留中文。不要把文字烘焙进实际 UI 图片，按钮和说明全部由本地化资源渲染。

| English | 简体中文 |
| --- | --- |
| Create / Library / Profile | 创作 / 资产库 / 我的 |
| Camera / Photos / Files | 拍照 / 相册 / 文件 |
| Add a reference | 添加参考图 |
| Use this photo | 使用这张照片 |
| What should it become? | 你想把它变成什么？ |
| Generate 3 concepts | 生成 3 张概念图 |
| Choose a concept | 选择概念图 |
| Refine this concept | 调整这张概念图 |
| Generate 3D asset | 生成 3D 资产 |

| Adjust model direction | 调整模型朝向 |

允许标题换行及按钮适度扩展；动态数量使用本地化格式。切换语言不清空创作草稿。用户输入中文提示词时，不能因界面是英文而要求重输。

## 五、交付检查与实现前整理

已经逐张查看三张设计板：主要流程连续，输入图、选中概念与结果角色在视觉上可追踪；没有角色主体被边界截断；每页主要按钮和选择状态可辨认。这里只做设计图检查，没有完成真机触控、可访问性或性能验收。

进入 SwiftUI 实现前需要统一几处栅格图细节：

- 页 05 / 06 顶部头像在最终组件中明确作为账户入口，不能混作参考图按钮；参考图用独立按钮。
- 页 09 的资产行必须使用生成资产缩略图，设计图里出现的真实猫照片需替换。
- 提示词字符计数来自实际文本，图里的计数为示意；若无明确限制，首版可省略计数。
- 页 08 的 68% 仅为画面示例；没有可靠后端百分比时，显示阶段和不定进度。
- 底部导航图标在三张设计板中有细微差异，落地时共用同一个导航组件。
- 设计图里的游戏氛围图不可用来宣传现有游戏的实际画质；上线封面优先取真实游戏截图。

第一版实施顺序建议：照片与提示词草稿 → 概念版本和确认 → 任务恢复 → 3D 查看与导出 → 资产库同步 → 兼容游戏入口。账户、安全、收费及任务可靠性仍需遵循[商业策略报告](../../business/3D_CRAFT_STRATEGY_2026-09-09.zh-CN.md)中列出的真实边界。
